# Secure Prompt Engineering for Memory-Safe C Code Generation Using Large Language Models

This repository contains the experimental artefacts for an MSc dissertation completed at WMG, University of Warwick. The project investigates how different prompt-engineering strategies affect the security and functional correctness of C code generated by large language models (LLMs), with particular attention to memory-safety weaknesses.

## Experimental design

The experiment compares three LLM families:

- DeepSeek
- Gemini
- Qwen

Each model was evaluated using four prompting strategies:

1. **Baseline** — the task prompt without an additional security instruction.
2. **Simple Security Prompt** — the task prompt supplemented by a short security instruction.
3. **General Secure C Principles (GSCP)** — the task prompt supplemented by general secure-C guidance.
4. **Security Design First (SDF)** — a design-oriented prompt that asks the model to consider security requirements before generating code.

The benchmark contains 40 programming tasks. Each model–strategy–task combination was repeated eight times, producing:

```text
3 models × 4 strategies × 40 tasks × 8 repetitions = 3,840 C programs
```

The generated programs were assessed using functional tests and a security-evaluation pipeline comprising conservative source-pattern checks, compiler checks, runtime smoke tests, sanitizers, and optional auxiliary static-analysis tools.

## Repository structure

```text
MSc Project/
├── Code/                  Generated C programs, organised by model and strategy
├── Data Sheet/            Benchmark prompts, task metadata, test cases, CWE selection, and sensitivity results
├── Functional  Results/   Stored functional-evaluation outputs
├── Security Results/      Stored security-evaluation outputs
├── Script/                Python scripts used to prepare and evaluate the C programs
└── Special_Code/          Separately retained exceptional or specially handled samples
```

The directory name `Functional  Results` contains two spaces and is preserved here to match the original experiment directory.

### Main data files

- `Data Sheet/llm_prompt_dataset.csv` — 40 neutral task prompts.
- `Data Sheet/prompt_dataset.csv` — task prompts with categories, CWE metadata, risk focus, and expected behaviour.
- `Data Sheet/functional_test_cases.csv` — functional test definitions for the 40 benchmark tasks.
- `Data Sheet/weakness_selection_table.csv` — the selected weakness categories and associated secure-design checks.
- `Data Sheet/sensitivity_results.csv` — results from the security-score sensitivity analysis.

### Evaluation scripts

- `Script/functional_check.py` — compiles the generated C files, runs task-specific functional tests, and writes a functional-results CSV file.
- `Script/security_scan.py` — performs conservative security checks and can run compiler, sanitizer, smoke-test, Cppcheck, and Clang Static Analyzer stages.
- `Script/rename_c_from_header.py` — previews or applies task-ID-based renaming of C files using identifiers found on their first lines.

## Requirements

- Python 3.10 or later
- GCC for the default functional-testing workflow
- GCC and/or Clang for compilation and sanitizer checks
- Cppcheck and Clang Static Analyzer for the optional auxiliary static-analysis stages

The Python scripts use only the Python standard library. Availability and behaviour of compilers and sanitizers may vary by operating system.

## Reproducing the evaluations

Run the following commands from the repository root. Paths are quoted because some directory names contain spaces.

### Inspect the functional test cases

```powershell
python "Script/functional_check.py" --dataset "Data Sheet/prompt_dataset.csv" --list-cases
```

### Run the functional evaluation

The following command scans all generated C programs recursively and writes a newly reproduced result file:

```powershell
python "Script/functional_check.py" --src "Code" --dataset "Data Sheet/prompt_dataset.csv" --out "functional_results_reproduced.csv" --jobs 4
```

Add `--sanitize` to compile with AddressSanitizer and UndefinedBehaviorSanitizer where supported. Use `--task F001` to evaluate a single task before running the full dataset.

### Run the security evaluation

Full evaluation:

```powershell
python "Script/security_scan.py" --src "Code" --recursive --out "security_results_reproduced"
```

Faster custom static-check-only evaluation:

```powershell
python "Script/security_scan.py" --src "Code" --recursive --static-only --out "security_results_static_only"
```

The full security workflow can generate `summary.csv`, detailed findings, compilation results, runtime results, Cppcheck results, Clang Static Analyzer results, and supporting logs in the selected output directory. Tool availability is recorded by the script; exact results can therefore depend on the local analysis environment.

### Preview task-ID-based file renaming

This command only previews changes:

```powershell
python "Script/rename_c_from_header.py" "Code" --recursive
```

The script renames files only when the additional `--apply` option is supplied.

## Interpretation and limitations

- The repository contains research artefacts rather than production-ready software.
- Security scores and scanner findings are operational measurements produced by the documented evaluation procedure; they are not formal proofs that a program is secure or insecure.
- Functional success on the supplied test cases does not establish correctness for every possible input.
- Reproduced compiler, sanitizer, and auxiliary-tool results may differ across platforms and tool versions.
- Model outputs are stochastic, so newly generated samples may differ from the archived samples in this repository.
